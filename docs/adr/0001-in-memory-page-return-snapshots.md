# 页面返回采用实例级像素快照

盒记的可滚动父页面统一使用页面实例级内存快照恢复“返回现场”：共享 composable 协调刷新与像素恢复，但滚动、筛选和草稿状态仍由当前页面实例持有。返回时不记录或定位业务数据条目，避免条目状态变化、排序移动或删除把用户带到另一处。这样既能在 `navigateTo → navigateBack` 的页面栈内可靠恢复，又能在页面卸载时自然清理，避免全局 Pinia、模块级缓存或本地持久化引入过期键、跨会话旧状态和额外失效规则。

## Considered Options

- 只依赖页面栈保留：返回刷新和条件渲染可能重建滚动容器，无法保证位置。
- 每页独立实现：改动局部，但规则、边界和异常处理会逐页漂移。
- 全局 Pinia 或本地持久化：能够跨页面甚至跨会话保存，但生命周期超过本需求，必须额外维护页面键和失效策略。
- 页面实例快照加共享 composable：统一行为，同时让状态生命周期与导航栈一致，因此采用。

## Consequences

- 现有两类滚动页面分别通过内部滚动适配和原生页面滚动适配接入，不批量改造页面结构。
- 数据变化时仍恢复离开前像素；返回后没有内容时回到顶部，不执行条目或相邻项定位。
- 页面触摸、系统返回和程序化滚动需要 HBuilderX Android 真机回归，CLI 只能验证类型、静态规则和编译。
