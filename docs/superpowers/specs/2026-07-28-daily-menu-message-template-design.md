# 每日菜单与社群文案模板设计

> 2026-07-28 经逐项访谈确认。本文是本增量的产品边界与验收依据。

## 目标

为盒饭档口提供“提前维护一周菜单 → 套用固定社群文案 → 一键复制”的本地工作流，不把菜单并入订单、价格或统计模型。

## 每日菜单

- 一天一条，以 `menu_date` 唯一；包含可换行的午餐、晚餐文本，至少填写一项。
- 新建默认当天；保存时可直接进入下一自然日并清空菜品。下一日已有菜单时进入已有记录。
- 今天及未来按日期升序展示；过去日期作为历史菜单按日期倒序展示。允许补录过去日期。
- 日期冲突不覆盖、不合并；新增或改期时引导进入已有记录。
- 菜单可新增、编辑、复制和硬删除，不保留编辑版本或回收站。
- 复制入口位于当前列表、历史列表和已保存的编辑页，始终使用当前默认模板。

## 文案模板

- 模板名称必填且唯一；任一时刻至多一个默认模板。首个模板自动成为默认。
- 默认模板用于菜单复制，不在每次复制时弹出模板选择。
- 模板支持新增、编辑、设为默认、硬删除、历史查看和版本恢复。
- 每次名称或正文发生实际变化时，先保存编辑前快照；原样保存不产生历史。
- 历史无限保留，记录名称、正文和时间，不记录默认状态。恢复前先快照当前内容。
- 删除模板同时删除全部历史。删除默认模板且仍有其他模板时，必须先选择接替模板；最后一个模板允许删除。
- schema v6 迁移内置“日常午晚餐”默认模板；用户主动删除全部模板后，后续启动不重新生成。危险清空会恢复内置模板。

## 模板语法与渲染

支持以下标记：

```text
{{日期}}
{{#午餐}}
{{日期}}午餐🍱
{{午餐}}
{{/午餐}}
{{#晚餐}}
{{日期}}晚餐🍱
{{晚餐}}
{{/晚餐}}
```

- `{{日期}}` 输出不补零的 `M月D日`，可放在任意位置并重复。
- `{{午餐}}`、`{{晚餐}}` 必须位于对应条件区块；区块必须闭合且不能嵌套。
- 对应餐次为空时删除完整区块；区块之外的固定文字原样保留。
- 渲染后删除行尾空格、首尾空行，并把连续多个空行压成一个空行；餐次文本内部换行保留。
- 未知、未闭合、嵌套或位置错误的标记禁止保存，编辑页实时给出错误和示例菜品预览。
- 最终只写入系统剪贴板；模板不包含 `@所有人`，群提醒由用户在社群中手动完成。

## 导航与视觉

- 保留今日 / 订单 / 统计 / 我的四个底部 Tab。
- 今日页增加“社群菜单”快捷入口；我的页增加“菜单管理”和“文案模板”。
- 表单继续使用 `uni-forms`、`uni-forms-item`、`uni-easyinput` 和 `uni-datetime-picker`。
- 页面沿用 `$hej-*` 浅色 token、连续白色表面和固定确认区；模板编辑页以带蓝色边线的“社群文案预览纸条”作为唯一识别点。

## 数据、备份与删除

- 新增 `daily_menus`、`message_templates`、`template_versions` 三张表；SQLite 仍是唯一持久层。
- 版本历史通过外键级联随模板删除；所有多表写入使用 `tx()`。
- schema v6 备份必须包含三张新表；v1-v5 旧备份可导入，菜单为空并补内置默认模板。
- schema v6 中“用户已删除全部模板”的空状态应可完整备份恢复，不在启动或导入时偷偷重建。
- 危险清空删除菜单、模板和版本历史，并恢复内置默认模板与 5 个默认支出分类。

## 验收标准

- 同一日期不能创建两条菜单；改期冲突不覆盖数据。
- 午餐或晚餐单独存在时能保存；二者同时为空不能保存。
- 缺餐复制会删除完整餐次区块，保留分隔线和固定说明，最终无三连空行。
- 菜品中的多行和 `$&`、`$1` 等普通字符按原文输出。
- 默认模板切换、删除接替、名称唯一、编辑快照和恢复快照符合上述规则。
- fresh schema、v5 → v6 迁移、v1-v6 备份兼容和危险清空均保持事务完整。
- `pnpm test`、`pnpm type-check`、`pnpm lint`、`pnpm build:h5`、`git diff --check` 通过；Android SQLite、剪贴板、表单触摸和页面视觉由 HBuilderX 真机回归。
